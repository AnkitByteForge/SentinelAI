# Changes

## 2026-08-27 — production hardening: no known gaps left before deployment

- **Security fixes (the two real deployment blockers)** — CORS origins now come from `CORS_ALLOWED_ORIGINS` (`app/config.py`, `app/main.py`) instead of a hardcoded `localhost:3000`. The dashboard no longer holds an API key client-side: `frontend/app/api/gateway/[...path]/route.ts` (a real server-side proxy, not a `next.config.js` rewrite — rewrites can't add headers) injects `Authorization` server-side from `SENTINEL_API_KEY`; `frontend/lib/api.ts` (dead code, unused, duplicated `page.tsx`'s own fetch logic) was deleted, and `page.tsx` now calls the proxy with no client-side key at all. Provider base URLs (`GROQ_BASE_URL`/`GEMINI_BASE_URL`) are also now configurable, which is what makes the load-test mock provider possible.
- **Distributed circuit breaker** — `services/circuit_breaker.py` rewritten to store state in Redis (one hash per provider), with an atomic `HINCRBY` for the failure counter and a `SET NX` lock around the `OPEN` transition so concurrent replicas don't double-fire webhooks. Falls back to a local in-memory copy if Redis is down. All registry methods are now `async`, rippling into `routers/gateway.py`, `routers/observability.py`, and `services/health.py`.
- **Full Alembic migration coverage** — new migration `0002_requests_cache` creates `requests`, `cache_entries`, and the cache's HNSW index (folding in what the now-deleted `create_hnsw_index.py` script used to do manually). `db/database.py`'s `init_db()` no longer calls `Base.metadata.create_all()` — it only ensures the `vector` extension exists; Alembic is the sole source of schema truth. (Revision IDs are intentionally short — `alembic_version.version_num` is `VARCHAR(32)`, and the first draft of this migration's ID overflowed it.)
- **Structured logging** — new `app/logging_config.py` (stdlib `logging`, JSON lines to stdout, configured once per process). Every `print(...)` across `routers/gateway.py`, `services/circuit_breaker.py`, `services/webhook.py`, and `app/tasks.py` replaced with leveled, `extra=`-tagged logger calls (request IDs threaded through where available). Also fixed a real bug found along the way: `services/cache.py` loaded the embedding model **eagerly at import time**, unconditionally — contradicting `PRELOAD_EMBEDDING_MODEL`'s own docstring ("...instead of lazily on first cache check"). It's lazy now, which also happens to make importing the app fast and independent of the model even being loadable.
- **Automated test suite** — `backend/tests/unit/` (circuit breaker transitions incl. webhook-fires-only-on-transition, rate limiter windowing + Redis-down degradation, API key hash/rotate/revoke, cost calculation, webhook HMAC signing, health rollup rules) and `backend/tests/integration/` (`/v1/chat`, `/v1/keys`, `/health*`, `/v1/circuit/*`, `/v1/webhook/*` via real HTTP through `httpx.ASGITransport`). `tests/conftest.py` spins up a real Postgres+pgvector via `testcontainers`, fakes Redis (`fakeredis`), and mocks the two LLM providers — no external dependencies, no cost. `requirements-dev.txt` and `pyproject.toml` (pytest + ruff config) added.
- **Heavy load-test suite** — `tests/mock_provider.py` (stand-in Groq/Gemini with injectable latency/failure rate), `tests/locustfile.py` (realistic-mix and infra-stress scenarios), `scripts/loadtest_failover.py` (automated: force the mock Groq to 100% failure, assert zero failed requests and a confirmed circuit-breaker transition), and `docker-compose.loadtest.yml` (points the gateway at the mock provider). Not run against real infrastructure in this session — see the README's "Load testing" section for why (this sandbox's Docker was too resource-constrained to be representative) and the exact commands to run it yourself.
- **CI/CD** — `.github/workflows/ci.yml`: lint (`ruff`) + test (`pytest`, using the same testcontainers/fakeredis setup as local dev — no GitHub Actions `services:` block needed) + a build-check for both Dockerfiles, on every push/PR.
- **Docker hardening** — `.dockerignore` added to both `backend/` and `frontend/` (closes a real one: without it, `COPY . .` would have baked `backend/.env` — API keys — into an image layer on any machine that had one locally). Both Dockerfiles rewritten multi-stage with a non-root user. `docker-compose.yml` gained per-service health checks (`backend`: HTTP `/health/live`; `worker`: `celery inspect ping` — they can't share one check, since only `backend` serves HTTP). Also fixed real bloat: `torch` was resolving its default GPU/CUDA build inside a CPU-only container (~530MB torch wheel plus ~366MB+ of unused `nvidia-cudnn`/`cuda-toolkit` packages). Fixed with a separate `pip install --extra-index-url https://download.pytorch.org/whl/cpu torch==2.11.0+cpu` step in the Dockerfile *before* installing the rest of `requirements.txt` — putting `--extra-index-url` directly in `requirements.txt` instead was tried first and rejected: it makes pip consider every package from both indexes, which produced a spurious hash mismatch on an unrelated dependency.
- **Lint** — `ruff` (added in the test-suite work above) found 32 real issues across the codebase (unsorted imports, missing trailing newlines, one unused import, one `== False` comparison that should be SQLAlchemy's `.is_(False)` — ruff's own auto-suggestion of `not CacheEntry.is_stale` would have been wrong there, since `not` doesn't produce a SQL comparison the way `.is_()` does). 30 auto-fixed, 2 fixed by hand. Two Pydantic v2 deprecation warnings (`class Config` → `model_config`) cleaned up alongside.

### Verified

- `pytest`: **65 passed** (unit + integration, testcontainers Postgres + fakeredis + mocked providers), 0 failed, in ~150s.
- `ruff check .`: all checks pass.
- `alembic history`/`alembic upgrade head` resolve the full `0001_api_keys` → `0002_requests_cache` chain correctly against a real Postgres (via the same testcontainers instance pytest uses).
- `docker-compose config` / `docker-compose -f docker-compose.yml -f docker-compose.loadtest.yml config` both parse cleanly.
- Frontend Docker image **builds successfully** end to end (`docker build ./frontend`) — this surfaced and fixed a real bug: `node:20-alpine` already ships a non-root `node` user at uid/gid 1000, so creating a new user at the same gid fails the build; fixed by reusing the image's own `node` user instead of creating one.
- Backend Docker image: dependency installation was verified working correctly (including the CPU-only torch fix above, and a `requirements.txt` encoding gotcha — writing it with this session's file-write tool silently re-encoded it to UTF-16, which pip can't parse as a requirements file; fixed by writing it with an explicit UTF-8 encoding instead), but the full image build was not confirmed to complete inside this session — this sandbox's Docker daemon was under heavy contention (18 unrelated containers actively running, 30GB+ of images, 14GB+ of build cache) shared with what `pytest`'s testcontainers also needed, and letting the ~10-minute backend build keep running was starving the test run. The build was stopped in favor of confirming pytest, which matters more. Worth a `docker build ./backend` on a clean machine before deploying, though there's no specific reason to expect it to fail — the earlier attempt (before being stopped for resources, not for an error) got through the CPU-torch install and well into the main `requirements.txt` install successfully.
- The previous round's known gap (below) is fixed, not just documented around: `services/cache.py`'s embedding load is now lazy (see "Structured logging" above), and the corrupted local HuggingFace cache that caused it (a stale `main` snapshot missing `1_Pooling/config.json`, and a second cached snapshot using the pre-rename `word_embedding_dimension` key instead of `embedding_dimension`) was root-caused and patched — the real model loads and produces 384-dim embeddings correctly in this sandbox now. That patch is local-machine-only (`~/.cache/huggingface`); it doesn't affect Docker/CI builds, which download a fresh, correctly-versioned cache regardless.

## 2026-08-24 — reliability and ops features

- **API key management** — added an `api_keys` table (Alembic migration `0001_add_api_keys`), a `services/api_keys.py` service for generation (`sk-sent-<32 hex>`), SHA-256 hashing, Redis-cached (60s) resolution, and rotation, plus `routers/keys.py` (`POST/GET /v1/keys`, `DELETE /v1/keys/{id}`, `POST /v1/keys/{id}/rotate`) gated by a new `verify_master_key` dependency. `verify_api_key` in `routers/gateway.py` now resolves either the master admin key (`API_KEY` in `.env`, kept for backward compatibility) or a per-tenant key.
- **Per-key rate limiting** — added `services/rate_limiter.py`, a Redis-backed fixed-window token bucket keyed by `ratelimit:{key_hash}:{window_minute}`, wired into `verify_api_key`. Exceeding a key's limit returns HTTP 429 with `X-RateLimit-*`/`Retry-After` headers; successful requests carry `X-RateLimit-Limit`/`X-RateLimit-Remaining`. Redis being unreachable degrades to allowing the request rather than blocking traffic. `GET /v1/keys` reports each key's current-window usage.
- **Circuit breaker webhook** — added `services/webhook.py` (HMAC-SHA256-signed HTTP POST, 5s timeout, never raises) and two Celery tasks (`send_webhook`, delivery; `touch_api_key`, last-used timestamps) in `app/tasks.py`. `CircuitBreakerRegistry.record_failure`/`record_success` in `services/circuit_breaker.py` now detect the `CLOSED→OPEN` and `→CLOSED` transitions specifically (not every failure) and fire a webhook via Celery. Added `GET /v1/webhook/config` and `POST /v1/webhook/test` to `routers/observability.py`.
- **Detailed health check** — added `services/health.py`, running database, Redis, Celery queue-depth, and per-provider circuit checks concurrently (`asyncio.gather`) with independent timeouts. Replaced `/health` in `main.py` with a `healthy`/`degraded`/`unhealthy` rollup that returns HTTP 503 when the database or Redis is unreachable, and added `/health/live` (bare liveness) and `/health/ready` (full readiness) for Kubernetes-style probes.
- **`.env.example` + bootstrap script** — rewrote `backend/.env.example` to document every setting now in `Settings` (Redis/Celery URLs, API key cache TTL, default rate limit, webhook config, health-check timeouts), added `scripts/bootstrap.py` (checks Docker, seeds `.env`, starts Postgres+Redis, waits for Postgres, runs `alembic upgrade head`, mints a default API key), and added `postgres`, `redis`, and `worker` services to `docker-compose.yml` (previously only `backend`/`frontend` were defined) with health checks, memory limits, and optional `WEBHOOK_URL`/`WEBHOOK_SECRET` passthrough.

### Supporting changes

- `app/config.py` — added `redis_url`, `celery_broker_url`, `celery_result_backend`, `api_key_cache_ttl_seconds`, `default_rate_limit_per_minute`, `webhook_url`, `webhook_secret`, `webhook_timeout_seconds`, `health_db_timeout_seconds`, `health_redis_timeout_seconds`, `celery_queue_depth_degraded_threshold`. `app/worker.py`'s Celery broker/backend URLs now come from `Settings` instead of being hardcoded to `localhost`.
- `app/db/models.py` — added the `ApiKey` model. Unlike `RequestLog`/`CacheEntry`, its schema is Alembic-managed, not created via `Base.metadata.create_all()`.
- `app/services/redis_client.py` — new shared async Redis client (`redis.asyncio`), closed alongside the HTTP client pool in `main.py`'s lifespan shutdown.
- Alembic scaffolding added under `backend/alembic/` (`alembic.ini`, `env.py`, `script.py.mako`) — this is the first migration in the repo; `requests`/`cache_entries` remained on the pre-existing `create_all()` path at this point (fully migrated in the next round, below).
- `README.md` — local setup now leads with `python scripts/bootstrap.py`; fixed several statements that this change made inaccurate (the `docker-compose.yml` service list, the `/health` response shape, the "what production would look like" items for API keys and rate limiting), and updated the project structure tree.
